# Multiple-choice follow-up block in the Jarvis 007 chat panel - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jarvis 007 embeds a hidden block at the end of its answer; the dashboard strips it out and draws it as clickable buttons right under the chat bubble, and clicking one sends it as if the user had typed it.

**Architecture:** Follow exactly the path of the `JAVIS_METRICS` block that already runs in the project: the model embeds an HTML comment `<!-- JAVIS_ASK: {...} -->` at the end of its response, and the client strips it with a regex in the `response` branch of the WebSocket. It does not touch the MCP hub or the engines, so it runs on every brain through the system prompt alone. The new logic lives in a single file `dashboard/chat-ask.js`; `app.js` only gets three hook points. On the server side, one pure function in `channel_context.py` downgrades the block to a numbered list for Telegram.

**Tech Stack:** Plain ES5-style JavaScript IIFE (no build step, no framework), Python 3.12, FastAPI, tests are scripts run directly (`python test_x.py`, `node test_x.js`).

## Global Constraints

- **ABSOLUTELY no em dash character (U+2014)** anywhere: code, comments, docs, display strings. Use a hyphen `-` or rewrite the sentence. This is a hard project rule (CLAUDE.md).
- Comments follow the convention of the file being edited, as verified (in the Vietnamese original, comments were written with or without diacritics per file; this English edition simply uses English):
  - `dashboard/chat-ask.js` (new file): Vietnamese **WITHOUT DIACRITICS**, following the sibling file `chat-render.js`.
  - `dashboard/app.js`: Vietnamese **WITH DIACRITICS**, matching what the file already has.
  - `server/*.py`: Vietnamese **WITH DIACRITICS**, matching `channel_context.py`.
  - Strings DISPLAYED to the user are always written as proper text (never ASCII-stripped), even in `chat-ask.js` (for example `"Something else…"`).
- All text generated by the model is **untrusted**: it must be escaped before being put into HTML.
- Dashboard JS files follow the IIFE mold `(function () { "use strict"; ... })()`, expose the API through `window.X`, and have a `module.exports` branch at the end of the file so they can be tested with node. See `chat-render.js:484-491` as a template.
- Tests are scripts run directly that print `ok`/`FAIL` themselves and call `sys.exit(1)` on failure. Do NOT use pytest (CI runs each `python test_*.py` file).
- Adding a `<script>` to `index.html` requires a `?v=N` cache-bust parameter.
- At most 4 options per block. One block is one question. No multi-select.

Create `dashboard/chat-ask.js`:

```js
/* chat-ask.js - multiple-choice follow-up block for the Jarvis 007 chat panel.

   Jarvis 007 ends its answer with a hidden block:
     <!-- JAVIS_ASK: {"question":"...","header":"...","options":[{"label":"..","desc":".."}]} -->
   This file strips that block out, draws it as a row of chips under the answer bubble, and catches the click.
   Clicking a chip = sending exactly that label as a normal user message.

   Follows exactly the path of the JAVIS_METRICS block that already runs (app.js). Does NOT use the MCP hub, does not
   use the engines -> runs on every brain through the system prompt alone.

   Safety: all text in the block is model-generated -> escape everything before putting it into HTML.
   Note: do NOT use the em dash character anywhere. */
(function () {
  "use strict";

  var ASK_RE = /<!--\s*JAVIS_ASK:\s*([\s\S]*?)\s*-->/;
  var MAX_OPTS = 4;

  function esc(s) {
    return String(s == null ? "" : s)
      .replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;")
      .replace(/"/g, "&quot;").replace(/'/g, "&#39;");
  }

  // Strip the JAVIS_ASK block out of the text. ALWAYS returns clean with the block removed (even when the JSON is broken) -
  // a block with a syntax error must NOT be allowed to swallow the Jarvis 007 answer.
  function extract(text) {
    if (typeof text !== "string") return { clean: "", ask: null };
    var m = text.match(ASK_RE);
    if (!m) return { clean: text, ask: null };
    var clean = text.replace(ASK_RE, "").replace(/\n{3,}/g, "\n\n").trim();
    var ask = null;
    try {
      var o = JSON.parse(m[1]);
      var opts = (o && Array.isArray(o.options) ? o.options : [])
        .filter(function (x) { return x && typeof x.label === "string" && x.label.trim(); })
        .slice(0, MAX_OPTS)
        .map(function (x) {
          return { label: String(x.label).trim(), desc: String(x.desc == null ? "" : x.desc).trim() };
        });
      var q = (o && typeof o.question === "string") ? o.question.trim() : "";
      if (q && opts.length) {
        ask = { question: q, header: String((o && o.header) == null ? "" : o.header).trim(), options: opts };
      }
    } catch (e) {}
    return { clean: clean, ask: ask };
  }

  if (typeof window !== "undefined") {
    window.JavisAsk = { extract: extract };
  }
  if (typeof module !== "undefined" && module.exports) {
    module.exports = { extract: extract };
  }
})();
```

```js
  var MAX_LABEL = 40;
  function cut(s) {
    s = String(s || "");
    return s.length > MAX_LABEL ? s.slice(0, MAX_LABEL - 1) + "…" : s;
  }

  // Draw the chip row at the end of the .bubble of the Jarvis 007 message element.
  // live=false -> draw it already in the frozen state (used when restoring history).
  function render(msgEl, ask, live) {
    if (!msgEl || !ask || !ask.options || !ask.options.length) return null;
    var host = msgEl.querySelector(".bubble") || msgEl;
    var old = host.querySelector(".jv-ask");
    if (old) old.parentNode.removeChild(old);   // on re-render, replace; do not stack on top of each other
    var box = document.createElement("div");
    box.className = "jv-ask" + (live ? "" : " jv-ask-done");
    var tag = ask.header ? '<span class="jv-ask-tag">' + esc(ask.header) + "</span>" : "";
    var chips = ask.options.map(function (o, i) {
      return '<button class="jv-ask-chip" type="button" data-i="' + i + '" title="' +
        esc(o.desc || o.label) + '">' + esc(cut(o.label)) + "</button>";
    }).join("");
    box.innerHTML =
      '<div class="jv-ask-q">' + tag + esc(ask.question) + "</div>" +
      '<div class="jv-ask-row">' + chips +
        '<button class="jv-ask-chip jv-ask-other" type="button" data-other="1">Something else…</button>' +
      "</div>";
    box._ask = ask;              // keep the original to re-read the real label (not the truncated label)
    host.appendChild(box);
    return box;
  }

  // Freeze every live chip row. Called when a new message arrives (chip click or typed by hand):
  // scrolling back through history and clicking an old question would break the conversation thread.
  function freezeAll() {
    if (typeof document === "undefined") return;
    var boxes = document.querySelectorAll(".jv-ask:not(.jv-ask-done)");
    Array.prototype.forEach.call(boxes, function (b) { b.classList.add("jv-ask-done"); });
  }

  if (typeof document !== "undefined") {
    document.addEventListener("click", function (e) {
      var chip = e.target.closest ? e.target.closest(".jv-ask-chip") : null;
      if (!chip) return;
      var box = chip.closest(".jv-ask");
      if (!box || box.classList.contains("jv-ask-done")) return;   // history: clicking does nothing
      e.preventDefault();
      if (chip.dataset.other) {                                     // "Something else" = type it yourself, send nothing
        var inp = document.getElementById("chatInput");
        if (inp) inp.focus();
        return;
      }
      var ask = box._ask;
      var opt = ask && ask.options[+chip.dataset.i];
      if (!opt) return;
      chip.classList.add("jv-ask-picked");   // mark BEFORE sending: JavisSend will freeze the whole row
      if (typeof window.JavisSend === "function") window.JavisSend(opt.label);
    });
  }
```

```python
# ============================================================
# Downgrade control blocks to text for non-web channels
# ============================================================
# Jarvis 007 embeds control blocks in the form of HTML comments at the end of the answer for the dashboard
# to read (JAVIS_METRICS feeds the left panel, JAVIS_ASK draws the option buttons). Plain-text channels
# like Telegram do not understand these blocks, and md_to_mdv2 only escapes and does not strip,
# so without filtering the user sees the whole blob "<\!\-\- JAVIS\_METRICS: ...".
_CTRL_RE = re.compile(r"<!--\s*JAVIS_([A-Z_]+):\s*([\s\S]*?)\s*-->")
_MAX_ASK_OPTS = 4


def _ask_to_text(payload: str) -> str:
    """JSON of the JAVIS_ASK block -> question + numbered list. Broken JSON -> empty string.

    A Telegram user just replies "1" and that is it: Jarvis 007 reads "1" in the context of the question
    it just asked and understands it, no state needs to be stored.
    """
    try:
        o = json.loads(payload)
    except Exception:
        return ""
    if not isinstance(o, dict):
        return ""
    q = str(o.get("question") or "").strip()
    opts = [x for x in (o.get("options") or [])
            if isinstance(x, dict) and str(x.get("label") or "").strip()]
    if not q or not opts:
        return ""
    lines = [q]
    for i, x in enumerate(opts[:_MAX_ASK_OPTS], 1):
        lines.append(f"{i}. {str(x['label']).strip()}")
    return "\n".join(lines)


def strip_control_blocks(text: str) -> str:
    """Strip every <!-- JAVIS_*: ... --> block out of the text.

    JAVIS_ASK -> replaced by the question + numbered list. Any other block -> dropped entirely.
    A block with a syntax error is dropped too: a broken block must NOT be allowed to swallow the answer.
    """
    def _sub(m):
        if m.group(1) == "ASK":
            t = _ask_to_text(m.group(2))
            return ("\n\n" + t) if t else ""
        return ""

    out = _CTRL_RE.sub(_sub, text or "")
    return re.sub(r"\n{3,}", "\n\n", out).strip()
```

## Notes for the implementer

**Why not build a real `javis_ask_user` tool through the MCP hub.** That is how Claude Code really does it, and it allows asking IN THE MIDDLE of a task. It was considered and rejected: the hub is HTTP, so the session would have to be stuffed into the MCP config header for every turn (the config file is cached per mode, not per session), timeouts would have to be handled, along with the user hitting F5 while the server is hanging and waiting, and it would have to be done three times for the three engine paths. Meanwhile, in the Jarvis 007 chat panel nearly every follow-up question falls at the end of a turn. If asking mid-task is truly needed later, a tool-based approach can be layered on top: `JavisAsk.render()` is reused as is, only the source of the question changes from `data.type === "response"` to a new WebSocket event.

**Why the chips do not sit outside `.bubble`.** `.msg-javis` is a flex-row containing `.bubble` and the copy button (`style.css:401`). Putting the chips in as its third child would place them to the RIGHT of the bubble. So `render()` attaches the chips inside `.bubble`.

**Why `render()` must be called AFTER assigning `innerHTML`.** The `response` branch of `app.js` overwrites `bubble.innerHTML` with the final markdown version. Calling `render()` before that line would wipe the chips right away.

**Why the chips do not flicker during streaming.** `chat-render.js:246` already swallows every HTML comment, including an UNCLOSED comment at the end of the string. Nothing more needs to be done.
