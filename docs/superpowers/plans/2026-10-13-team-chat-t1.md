# Team chat group: T1 plan (core, Limited permission)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the first genuinely useful team chat flow, end to end: create a group, add agents, pick a lead, assign to everyone or by @, a queue with Priority, coordination, results landing in the right group. Limited permission mode, fixed default caps.

**Architecture:** architecture A (spec section 3).
- Conversation runs on the channel session `team:<id>`; `messages` gains a sender column.
- Team work is the `team` lane in the Kanban `tasks` table, with `team_*` statuses; queue order and version live in the same `kanban.sqlite3` file so CAS and the claim step share one transaction.
- The `team.sqlite3` store holds groups, members, steps, the turn ledger and busy locks.
- The runner `team_runner.py` receives the engine through an injected dependency, so tests run entirely on a fake engine.

**Tech Stack:** Python 3.12, FastAPI, SQLite; plain JS in `dashboard/`; tests in `tests/python`, `tests/js`.

**Spec:** [2026-10-13-team-chat-design.md](../specs/2026-10-13-team-chat-design.md). D1 to D7 settled (2026-10-13).

## Global Constraints

- Version 0.111.0 (reserved in PR #628, stacked on #627).
- New identifiers in English; comments, UI text and docs in Vietnamese with diacritics.
- No em dash (U+2014) anywhere.
- New on-screen text has keys in `vi.json` and `en.json`.
- Python writes files with `encoding="utf-8", newline="\n"`.
- No real model calls; every test uses a fake engine. No merging, no touching the VPS.
- Default caps (spec 12.3, D7): 12 turns per job; 8 steps per job; help depth 2; no reverse help requests; 2 no-progress turns; 3 @ per message; 100 turns per group per day; 1 running job per group; 2 groups running at once; 1 concurrent turn per agent (D3); busy-lock wait 30 minutes.
- Routing (D1, D2): a message without @ is answered by the lead; team work is created by the "Assign work" switch or when the owner accepts a proposal from the lead.

## Review Focus

1. **Resending the same `client_msg_id` after a network drop:** no new message, no new job, no new turn.
2. **Two Priority commands almost at once from two tabs, or just as the dispatcher claims a job:** one side gets 409; never two `team_running` jobs in one group.
3. **A member removed or the lead changed while a turn is running:** the result is saved with a label, not applied.
4. **An agent deleted and recreated with the same slug:** it is not a member and does not receive the old job.
5. **The model returns a bad `JAVIS_TEAM` block** (broken JSON, unknown op, assigning to someone outside the group, reverse help request): drop the op, add a note, make no extra turn beyond the caps.
