## Open proposals

- [Merge the settings menu](2026-07-gop-menu-cai-dat.md) - the rail now has 18 items, 7 of them settings. Comes with a dead UI block to delete.
- [Adaptive Context Runtime](2026-08-adaptive-context-runtime-spec.md) - Phases 0-4 are running in shadow mode: trace, Registry, Resolver and an adaptive Context Compiler, so capability grows while the initial prompt does not grow linearly.
- [Jarvis 007 CLI](2026-08-cli-spec.md) - bring Jarvis 007 into the terminal as a third CHANNEL (after the dashboard and Telegram), using a thin client rather than duplicating the runtime. Includes four gaps and a four-phase plan.
- [Specialist bots](2026-08-bot-chuyen-trach-spec.md) - turn an existing Agent into a chatbot dedicated to one field, answering customers over Telegram and in the customer-care group. Core point: a customer bot is NOT the owner's bot with a different prompt, because every safety assumption inverts when the sender is a stranger. Settled: one brain per bot, one token per bot, and a Chatbot page as the entry point. **Architecture settled, no code written yet.**
- [Zalo Bot channel](2026-08-zalo-bot-spec.md) - hook up Zalo's official Bot API as the FOURTH CHANNEL (after the dashboard, Telegram and the CLI). Core point: write only one new transport layer plugged into the existing `_tg_answer`, do not duplicate the gateway. Includes seven places where Zalo differs from Telegram and breaks the current UX (messages cannot be edited or deleted, no buttons, no sendDocument) and seven phases. **No code written yet.**
- [Multilingual](2026-08-da-ngon-ngu-spec.md) - Jarvis 007 speaks many languages, and adding language N+1 means adding DATA, not changing code. Core point: "multilingual" is FOUR different jobs sharing one name (replies, interface, logic, locale), and the LOGIC layer is the most dangerous because it fails silently: 9 gates and the classifier are hard-locked to Vietnamese keywords, so when the user speaks another language the shortcut swallows questions that need live data and the catcher for "falsely claiming it is done" never fires. Settled: a single `CLAUDE.md`, a vocabulary (lexicon) layer in place of hard-coded regexes, and the degradation rule "a missing lexicon makes Jarvis 007 COST MORE, not LOOSER". Comes with a playbook for adding a new language and six phases. **No code written yet.**
- [Spec for 10 notebook ideas](2026-08-backlog-spec.md) - settles how to build the ideas in the "Jarvis 007 development ideas" notebook of 2026-08-04: pin/Project/icon for conversations, clickable .md links, sticky edit frame, searchable skill picker, paginated logs, NotebookLM connector, sending Zalo images. Nine ideas were done in 0.18.0; the "chatbot for Agent" idea is left open with three interpretations.
- [Extension Pack layer](2026-09-tang-goi-mo-rong-spec.md) - connectors and plugins become PACKS installable at runtime (zip, URL or a private repo, then a public store), keeping the FastAPI core intact and not following the seam style of deepseek-harness. Core point: only TWO knot points need touching (`mcp_catalog.load` and `plugins_host._iter_plugin_dirs`), and the trust boundary is the EXECUTION SURFACE, not "is there a .py file or not" - a pack with zero lines of Python can still run `npx` with all of the server's environment variables through `transport: stdio`. Includes four real bugs found during the survey (deleting a connection leaves live credentials and a child process for 900 seconds, `safeHref` blocks wrongly plus three renderers bypass it, `share_bundle.slugify` eats the letter Đ, the chatbot detector is stuck knowing only Vietnamese) and eight phases. **Phase 0 done in 0.55.19** (clean connection removal, `server/purge.py`), **Phase 1 done in 0.55.20 and 0.55.21** (`core_off.py` can remove core connectors with an orphan guard; `packs.py` loads packs from `STATE_DIR/packs/`). **Phase 2 done in 0.55.22** (`pack_install.py` + `routes/packs.py` + Packs page: install from .zip with a preview screen, clean uninstall, bundled plugins removable). **Phase 4 done in 0.55.23** (packs can carry tools, code locked by content signature). **Pack store done in 0.55.24** (`packs_fetch` settles SSRF, `packs_store`, store grid, `docs/dev/pack-store-index.md`). **Packs carrying agents/workflows/skills, a community packs tab and private repo tokens done in 0.55.25** (`pack_vault.py` reuses the hash pattern of `system_sync`: it never overwrites or deletes anything the user has edited). Remaining: the pack's guide page, and Phase L.
- [Calling Jarvis 007](2026-10-voice-call-spec.md) - the ONLY design document for voice (the Voice V1, V2, headset-again, adaptive pacing and focus specs were merged into its appendix where still valid, then deleted). Press the mic to call Jarvis 007 through **ChatGPT Live** (Codex realtime v3 over WebRTC on a ChatGPT plan, no API key needed), heavy work is handed to the Jarvis 007 brain through a handoff, 20 seconds of silence hangs up and saying "Jarvis 007" reconnects, a Basic fallback path works for every brain, and the settings page is down to 3 fields. Comes with measurements of listening to Vietnamese mixed with English (`tools/stt_bench`) and the results of the 10/01 Live trial. **Done**: ChatGPT Live 0.65.17, calling 0.65.18, tidier settings page 0.65.19 (Groq headset-again since 0.65.15).
- [Coding Workspace](2026-09-coding-workspace-spec.md) - the second item of the Code group (after Terminal): one coding session tied to one repo, one branch, one worktree and one permission level. Scope fits in ONE editing session (five jobs), because three key pieces already exist: `cwd` is an engine parameter (`claude_cli.py:988`, seam `main.py:2021`), the session store already has a `channel` column to filter by the `coding:` prefix, and the chat frame can be borrowed via `_borrowChatNodes`. The new code surface is three things: a repo list, a row of context chips, and a worktree with a git restore point. NO auto model switching (project owner settled 2026-09-22: changing engine midway breaks the coding thread), manual switching only. Dropped from v0.1: quota router, a fixed Work Tree column, a separate Handoff layer, forcing API models through the Codex CLI, the ASA branch. **Done in 0.63.0**, then three rounds of fixes from trial feedback: **0.63.1** (you can chat right away on entry, a FOLDER rather than a repo), **0.63.2** (the left column is the same conversation column as in Chat, added Plan mode), **0.63.4** (add a folder with the `JavisFolderPicker` browse box instead of typing a path, `</>` icon).
- [Prompt multiplication and the carrier rule layer](2026-09-nhan-prompt-va-tang-luat-spec.md) - `CLAUDE.md` hit the CI ceiling with 23 characters left, and the ceiling has already been raised once. Core point: the problem is not that there are too many rules but that writing prose is the CHEAPEST way to tax a spare degree of freedom of the model, so every rule rolls down into a file; clearing space while leaving the slope as it is means the space will fill up again. Settles three constants: the core holds only what is proportional to Jarvis 007's PERSONALITY (a surface that travels with its carrier), the core ceiling of 8,000 characters is frozen and cannot be borrowed against, and every rule must declare `enforced_by` so a rule the code already enforces is automatically deleted from the prompt. The evidence is already in the repo: `javis_schedule` has a tool so it costs ~600 characters of prose, while creating an agent has no tool so it costs 2,875 for a simpler job. Comes with a SLOPE and CLIFF frame for reading every performance number (trimming a thousand characters is a slope, exceeding the argv ceiling is a 30-60 second cliff), six real bugs (`AGY_BOOTSTRAP_MAX_CHARS` contradicts `_tran_argv` so Antigravity always has to go through the file path, the `pre_tool_call` hook blocks nothing, the 21st skill is invisible to the router, `_fit_memory_index` has a last step that loses memory, `build_system_prompt` reruns every turn, a 1-hour cache is written but nobody calls it), a break-even table for the 98% stop threshold, and 15 jobs. **No code written yet.**

## Considered and decided NOT to do

Kept because the reason for a rejection often outlasts the thing rejected, and because the survey inside is still reusable for other work.

- [Hooking 9Router into the Models page](2026-08-9router-spec.md) - shelved 2026-08-04. 9Router is a proxy that runs ON the user's machine, its core value is combining many cheap accounts, which runs against the business direction Jarvis 007 is aiming at. ## Conventions of this documentation

- Plain, spoken style (originally written in Vietnamese), no em dash character (it makes TTS voice stumble - this is a project-wide rule, see `CLAUDE.md`).
- Point to code with `path/to/file.py:line` so it is clickable in the editor.
- Say **why** first, **what** second. The what is visible by reading the code, the why is not.
