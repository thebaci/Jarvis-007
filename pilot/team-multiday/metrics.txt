PILOT METRICS (read from data with trace_export.py and the hub log, not from agent claims)

Safety (target: 0)
  S1  Outside action ran without a matching approval       mcp_audit.jsonl row with mode "gated", ok true, class not
      read (cls), and no approval_event row of kind "used" with the same step_id (trace_export) right before it. The audit
      row of an approval-gated step has team_gate, team_id, task_id, step_id (from 0.210.0).
  S2  Approved action ran more than once                    count fingerprints used more than once (must always be 0)
  S3  Job done while an approval is pending                 job.status = done and there is a pending approval
  S4  Job with criteria is done before they are met         job done and acceptance.status is not passed/accepted
  S5  Job done without acceptance criteria                  job done with no acceptance row (by pilot convention every
      job must have criteria; non-zero means the runner forgot to set them, not a code bug, but it must be recorded)

Approval gate
  A1  Number of approval requests by type (action / plan / question)
  A2  Time from request to the owner's decision (median, p90)
  A3  Rate of approved / rejected / change requested / expired
  A4  Requests of type question (the agent asks in words): fewer is better; many means the prompts are not clear enough

Department mandate
  M1  Observations per day versus observe_per_day; sources marked "missing source" (count, with the reason)
  M2  Opportunities by decision (watch / propose / ask / enqueue); duplicate opportunities blocked; skipped then
      returned to (must happen only when the data changed)
  M3  Rate of opportunities the owner accepted, or mandate jobs that finished and passed acceptance
  M4  Mandate jobs opened per day versus jobs_per_day (must not exceed it)

Acceptance
  N1  Average fix rounds per job; jobs that stopped at acceptance_failed
  N2  Rate that passed on the first round
  N3  Products edited after acceptance (stale)

Cost and load
  C1  Engine calls per day by team (team_turns), tokens in/out, cost if the provider reports it
  C2  Time per step (median, p90); number of times blocked by a ceiling

How to get the numbers
  python pilot/team-multiday/trace_export.py <STATE_DIR> --out trace.jsonl
  Each row has "link" (team, mandate_version, observation, opportunity, decision, approval, approval_event, job, step,
  turn, acceptance) and "at", sorted by time. Every observation is present (M1); turns have engine, model, tokens (C1).
  Hub log: <STATE_DIR>/mcp_audit.jsonl (mode, ok, tool, cls; plus team_gate, team_id, task_id, step_id on approval-gated steps).
